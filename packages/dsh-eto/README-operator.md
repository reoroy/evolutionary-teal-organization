# ETO 使用手册（运营者版）

> 给每天用它干活的人。不谈实现，只讲怎么用、什么时候用、出问题怎么办。

## 一分钟看懂：三个入口

| 你想干什么 | 去哪儿 | 例子 |
|:--|:--|:--|
| **让 AI 改代码** | GitHub 开 issue，`@Roy-superagent` | 「在 README 补一段安装说明，只改这一处」 |
| **让 AI 评估一个方案** | DSH 侧栏 → **ETO 面板** → 写方案 → 点「评审」 | 「把 MCP 桥改成独立插件，可行吗」 |
| **日常对话里顺手用 ETO** | 直接在对话里说 | 「让几个 peer 评审下这个方案」 |

## 一、ETO 面板（侧栏那个 ETO 图标）

### 界面长这样

```
┌──────────────────────────────────────┐
│ ETO   ✓   0.1.9 · d23eed3        ↻   │  ← 版本 + 健康状态
├──────────────────────────────────────┤
│ ┌──────────────────────────────────┐ │
│ │ 你要做什么？…                     │ │  ← 写任务或方案
│ └──────────────────────────────────┘ │
│ [路由] [澄清] [评审] [完整流程]        │
├──────────────────────────────────────┤
│ 最近                            清空  │
│ ✓ 路由  给 README 加 CI 说明  230ms   │
│ ✗ 评审  把 MCP 桥改成插件   180000ms  │
└──────────────────────────────────────┘
```

### 四个按钮干什么

| 按钮 | 做什么 | 耗时 | 什么时候用 |
|:--|:--|:--|:--|
| **路由** | 判断任务类型（research/code/solution/knowledge），给执行建议 | 秒 | 不确定这事该怎么做时 |
| **澄清** | 检查你的指令是否模糊，给澄清选项 | 秒 | 派活前自查 |
| **评审** | 三个 peer 独立打分 → 审议 → 终审 | 慢（几十秒） | 方案取舍、风险判断 |
| **完整流程** | 路由 → 评审 → 存记忆，一条龙 | 慢 | 想要完整评估时 |

### ⚠️ 评审现在有个已知问题

**如果本机没启动 Ollama，评审会返回一堆 0.5 分，但界面显示「完成」。**

怎么判断是不是假的：
- 看展开后的 `concern` 和 `suggestion` 字段 —— **都是空字符串就是假的**
- 三个 peer 分数完全一样（比如都是 0.5）—— 也是假的

真评审的样子：
```json
{"peer":"researcher","score":0.75,
 "concern":"没有说明回滚路径",
 "suggestion":"补充失败时的降级方案"}
```

这个问题的修复方案在 issue #43 里评估中。

### 历史时间线

- 每条记录可以点开看完整 JSON
- **↻ 重跑**：把输入填回去再跑一次
- **导入到对话**：把这条结果（或错误）连同样例一起带进一个新会话，让 AI 接着干

> 「导入到对话」目前**未实机验证**，如果点了报「导入失败：…」，把错误发给管理员。

## 二、什么时候用面板，什么时候用对话

| 场景 | 推荐 | 为什么 |
|:--|:--|:--|
| 快速判断任务类型 | 面板「路由」 | 一点就出，不占对话上下文 |
| 方案要不要做 | 面板「评审」 | 结果是结构化 JSON，好对比 |
| 边聊边评估 | 对话里说「让几个 peer 评审」 | 评审结果能直接接下去讨论 |
| 需要多轮追问 | 对话 | 面板是一次性的 |
| 改代码 / 修 bug | GitHub 派 superagent | 有 CI 把关、有 PR 记录 |

## 三、派活给 superagent

在 GitHub 开 issue 或评论，写清楚，然后 `@Roy-superagent`：

```
在 reoroy/evolutionary-teal-organization 的 README.md 里补一段安装说明，只改这一处。

@Roy-superagent
```

### 之后会发生什么（全自动）

```
你开 issue
  → ETO 判定：这是要干活的 → 建工单
  → worker 开分支、改代码
  → 开 PR（description 里带 Closes #N）
  → CI 跑 9 个检查
  → 改动 < 200 行：自动合并；超过：等你合
  → issue 自动关闭
  → 飞书推你一条「✅ 工单跑完并合并」
```

### 写工单的三个要点

1. **说清改哪里**（文件名/函数名），别只说「优化一下」
2. **说清范围**（「只改这一处」「不要动其他文件」）
3. **说清验收标准**（跑什么命令、期望什么输出）

## 四、常见故障

| 现象 | 原因 | 怎么办 |
|:--|:--|:--|
| 面板全白 | client 代码报错 | 错误会显示红色文字，把它发给管理员 |
| 评审全是 0.5 分 | Ollama 没跑 | 见上面「评审现在有个已知问题」 |
| 「导入到对话」报错 | `agents.createSession` 签名不对 | 发给管理员，这是未验证的功能 |
| 派活没反应 | 判定为 ignore | 看判定原因：`bash sa-decisions.sh` |
| 工单卡在 queued | 闲时调度把任务排到了闲时 | 看 `sa-status.sh`，或让管理员临时关闲时 |
| 工单 failed 说额度 | provider 限流 | 换 provider（管理员操作） |

### 查状态的命令

```bash
cd ~/Nutstore\ Files/工作库/DeepSeek\ harness/19-superagent-ops/scripts
bash sa-status.sh      # 实例健康
bash sa-tickets.sh     # 当前工单
bash sa-decisions.sh   # 最近判定 + 原因码
```

## 五、在对话里直接用 ETO

不用开面板，直接说：

| 你说 | 会发生什么 |
|:--|:--|
| 「让几个 peer 评审下这个方案：…」 | 调 `eto_consensus` |
| 「这个任务该怎么路由」 | 调 `eto_route` |
| 「这计划靠谱吗，打个分」 | 调 `eto_peer_score`（**用当前对话的模型，不依赖 Ollama**）|
| 「记住 XXX」/「之前记的 XXX」 | 共享记忆读写 |
| 「这个指令是不是太模糊」 | 调 `eto_clarify` |

> 注意：`eto_peer_score` 走当前会话模型，是**唯一不受 Ollama 影响**的评审路径。
> 想立刻要个靠谱评分，用这个而不是 `eto_consensus`。

## 六、当前能力边界（别期待这些）

| 还不能做 | 说明 |
|:--|:--|
| 评审进度条 | 点完要等，中途看不到进度 |
| 评审结果对比 | 历史记录不能并排比较 |
| 面板内记忆浏览 | 记忆功能收在工具里，面板上没有专门界面 |
| 工具按 preset 隔离 | 切到别的 preset 也看得到 ETO 工具（只是没人格引导） |
| Watch/Cron 自动触发 | Loop 只实现了 Rework 和 Iteration |
